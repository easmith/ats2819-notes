# ATS2819: как перепрошить наушники с костной проводимостью на Actions

Записи по обратной разработке, рабочие инструменты и образы прошивки для платформы Actions
**ATS2819 / US281B**. Всё получено на наушниках с костной проводимостью, на которых нет марки,
которую мне удалось бы опознать: по Bluetooth они объявляются как `B18`, а USB-диск у них помечен
`AGP-S22` — это всё, что они о себе сообщают. Началось с «наушники говорят только по-китайски»,
закончилось русскими голосовыми подсказками в устройстве — через один кирпич и возвращение из него.

[English version](README.md) · [Оглавление документации](docs/ru/00-index.md) · **[Прочитать SAFETY.ru.md прежде чем что-то писать в устройство](SAFETY.ru.md)**

## Находка, ради которой стоит читать дальше

Если вы здесь потому, что чип Actions перестал загружаться после прошивки заводскими
загрузчиками: **данные, скорее всего, в порядке, а зерно — нет.**

Контроллер SPI перемешивает всё, что пишет во флеш, аппаратным рандомайзером. Зерно берётся из
одного из двух мест, выбор — бит 14 (`RAND_SEL`) регистра `SPI0+0x00`:

* бит установлен — зерно читается из программного регистра `SPI0+0x14`;
* бит сброшен — используется встроенное зерно чипа из eFuse. **Именно так читает загрузочное ПЗУ**,
  всегда.

Загрузчик `NorFwsc` из SDK этот бит ставит и латчит зерно из таблицы в собственном заголовке, а в
поставляемом загрузчике эта таблица нулевая. То есть он пишет образ, перемешанный нулевым зерном:
все контрольные суммы сходятся, содержимое побайтно верное — а ПЗУ, расшифровывая встроенным
зерном, видит шум, не находит загрузочную запись и уходит в ADFU. Лечится одним словом:

```
0xBFC2C308 (смещение 0x308 в NorFwsc.bin):  0x34794000  ->  0x34790000
            ori t9,v1,0x4000                ori t9,v1,0
```

Это `use_hw_seed()` в `tools/adfu_flash.py`, применяется по умолчанию. Вся история — включая
офлайн-декодер, который «подтвердил» незагружаемый образ, и почему он был неправ — в
[02-flash-format.md](docs/ru/02-flash-format.md) и [09-journey.md](docs/ru/09-journey.md).

## Что здесь есть

| Путь | Что это |
|---|---|
| `docs/ru/`, `docs/en/` | документация по-русски и по-английски — одинаковый набор файлов |
| `tools/` | рабочие скрипты: доступ по ADFU, MIPS-стаб, запись с проверкой чтением, сборка образа и подсказок |
| `firmware/stock/` | заводской образ прошивки того самого экземпляра, расшифрованный и сверенный по контрольным суммам — образ для восстановления |
| `firmware/prompts-ru-en/` | русские и английские подсказки и готовый к прошивке образ |
| `firmware/raw/` | сырое физическое чтение рабочего устройства — эталон формата на самом чипе |
| `notes/` | черновые записи по обратной разработке: адреса, дизассемблер |
| `scripts/bootstrap.sh` | приносит SDK и достаёт из него загрузчики — ничего этого в репозитории нет |

## С чего начать

```bash
scripts/bootstrap.sh                                    # SDK, загрузчики, .venv
.venv/bin/python -m pytest tests/ -q                    # проверки на компьютере, устройство не нужно
sudo .venv/bin/python tools/adfu_flash.py stock         # сухой прогон: общается с устройством, не пишет
```

Прошивка и приёмочное чтение, которое показывает, сможет ли загрузочное ПЗУ прочитать флеш, —
в [06-flashing.md](docs/ru/06-flashing.md). Свои подсказки — в [08-custom-prompts.md](docs/ru/08-custom-prompts.md).

## Границы применимости

* Проверено на **одном** экземпляре одного изделия. Все адреса, смещения и места правок относятся
  к той ревизии SDK; `scripts/bootstrap.sh` сверяет контрольные суммы загрузчиков, а инструменты
  громко предупреждают при несовпадении — но другой чип того же семейства потребует своей работы.
* Делалось на **macOS** (Apple silicon). Доступ к USB требует `sudo` и **libusb**
  (`brew install libusb`); без него у pyusb нет бэкенда, и инструменты об этом скажут. Из внешних
  программ нужны `ffmpeg`, `lame` и `binutils` ради `gobjdump` (дизассемблер MIPS16 — Capstone
  MIPS16 не умеет). Linux должен работать, не проверялось.
* Голос подсказок синтезирован локально командой `say` из macOS, так что опубликованный звук
  не лучше этого голоса. Пересборка — одна команда, результат побайтно воспроизводим.

## Что здесь не решено

* **Английские подсказки собраны, но недостижимы.** Они лежат в слоте языка 1 в `tts_rc.lib` —
  это родной заводской механизм второго языка, — но в заводской прошивке английских записей было
  ноль, и переключателя найти не удалось. Возможно, нужен код прошивки.
* **Сопряжения теряются при перепрошивке.** Они живут в последних 64 КБ чипа, вне области прошивки,
  и ничем здесь не сохраняются.
* **Прошивки для этого изделия нет нигде в публичном доступе**, кроме образа в этом репозитории —
  что неудивительно, раз у самого изделия нет названия, которое удалось бы найти. Если ваш
  экземпляр ему не подойдёт, отступать некуда.
* Путь обновления с диска (`UPGRADE.HEX` на собственном диске устройства) собран и проверен на
  компьютере, но **ни разу не прошит**, и безопасным он не является — см. [04-fwu-format.md](docs/ru/04-fwu-format.md).
